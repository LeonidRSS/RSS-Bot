# RSS-бот для Telegram

Бот следит за RSS/Atom-лентами и присылает новые посты в чат.

## Команды
- `/add <url>` — подписаться, новости будут приходить в текущий чат
- `/add <url> <@канал_или_id>` — новости будут публиковаться в указанный канал
- `/list` — список подписок
- `/remove <url>` — отписаться

## Публикация в канал вместо личного чата
1. Добавь бота в канал администратором с правом **Post Messages** (Публикация сообщений)
2. Узнай ID канала: если канал публичный — это его `@username`; если приватный — перешли любое сообщение из канала боту [@getidsbot](https://t.me/getidsbot), он покажет числовой ID вида `-1001234567890`
3. В чате с ботом (не в самом канале) отправь: `/add https://example.com/rss.xml @my_channel` — и новости из этой ленты будут приходить в канал, а не тебе в личку

## 1. Получи токен бота
1. Напиши в Telegram [@BotFather](https://t.me/BotFather)
2. Команда `/newbot`, следуй инструкциям
3. Скопируй токен вида `123456:ABC-DEF...`

## 2. Локальный запуск (проверить, что всё работает)
```bash
pip install -r requirements.txt
export BOT_TOKEN=твой_токен
python bot.py
```

## 3. Деплой на Railway (бесплатно)
1. Зарегистрируйся на [railway.app](https://railway.app) (можно через GitHub)
2. Залей эту папку в GitHub-репозиторий
3. В Railway: **New Project → Deploy from GitHub repo** → выбери репозиторий
4. Во вкладке **Variables** добавь:
   - `BOT_TOKEN` = токен от BotFather
   - `CHECK_INTERVAL_SECONDS` = `300` (необязательно, по умолчанию 5 минут)
5. Railway сам увидит `Procfile` и запустит бота как worker-процесс
6. Готово — бот работает 24/7

> Важно: убедись, что в настройках сервиса на Railway выбран режим **Worker**, а не Web — RSS-боту не нужен HTTP-порт.

## Как это устроено
- `bot.py` — вся логика: команды + фоновая проверка лент каждые `CHECK_INTERVAL_SECONDS`
- Подписки и уже отправленные записи хранятся в SQLite (`rss_bot.db`)
- На бесплатном тарифе Railway файловая система эфемерна (данные пропадут при редеплое) — для долгосрочного проекта позже можно подключить Railway PostgreSQL, но для старта SQLite достаточно

## Возможные доработки
- Поддержка нескольких чатов/групп — уже работает из коробки (подписки привязаны к chat_id)
- Кнопки для управления подписками вместо команд
- Ограничение частоты уведомлений, если лента очень активная
